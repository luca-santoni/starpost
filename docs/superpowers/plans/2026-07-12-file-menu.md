# Top-Bar "File" Menu Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `File` hover-dropdown (Add ▸ Files…/Folder…, Import data…, Export data…) as the first item in the main window's top bar, reusing the existing "Run batch" hover-menu machinery and the existing add/import/export code paths.

**Architecture:** StarPost is a PySide6 desktop app with a frameless main window whose single top bar (`TitleToolBar`) doubles as the menu bar. The "Run batch" button already implements hover-open dropdowns via `HoverMenuToolButton` + `HoverMenu` (`src/starpost/gui/widgets.py`). This plan (1) teaches `HoverMenu` that an open child submenu is a safe pointer region, (2) makes `FileListPanel`'s two add-dialog slots public, and (3) builds the File menu in `MainWindow._build_toolbar` wired to those existing slots. No new business logic anywhere.

**Tech Stack:** Python 3.11, PySide6, pytest.

**Spec:** `docs/superpowers/specs/2026-07-12-file-menu-design.md`

## Global Constraints

- Run the *full* suite only via `python scripts/run_tests.py` (per-file process isolation); single files directly with `python -m pytest tests/<file>.py -v` is fine.
- On a headless machine, prefix every pytest/run_tests command with `QT_QPA_PLATFORM=offscreen `.

- Menu labels that open dialogs end with `…` (matching the bar's "Export…" / "Settings…").

- Native OS dialogs only — do NOT introduce a non-native combined file/folder dialog (explicitly rejected in the spec).

### Task 1: `HoverMenu` keeps open while the pointer is over a visible child submenu

`HoverMenu.mouseMoveEvent` auto-closes the menu when the pointer strays more than `CLOSE_MARGIN` (50 px) beyond the menu or its owner button. A child submenu (the upcoming "Add ▸") is a separate popup window that can extend past that margin, so without this fix, moving deep into the submenu closes everything.

**Files:**
- Modify: `src/starpost/gui/widgets.py` (`HoverMenu.mouseMoveEvent`, lines ~351-374)
- Test: `tests/test_widgets.py` (append after `test_hover_menu_sibling_bar_does_not_close_over_owner`, ~line 291)

**Interfaces:**
- Consumes: existing `HoverMenu` (QMenu subclass), test helpers `_move_to(menu, global_pt)` and `_shown_hover_menu()` already in `tests/test_widgets.py`.
- Produces: `HoverMenu` behavior change only — no signature changes. Task 3 relies on a submenu created via `HoverMenu.addMenu("Add")` staying usable.

```python
def test_hover_menu_stays_open_over_visible_submenu(app):
    """A visible child submenu (e.g. File ▸ Add) is a separate popup that can
    extend past CLOSE_MARGIN; the pointer over it must not close the menu."""
    from PySide6.QtCore import QPointF, QRect

    from starpost.gui.widgets import HoverMenu

    btn, menu = _shown_hover_menu()  # noqa: F841 (keep btn alive)
    sub = menu.addMenu("Add")
    sub.addAction("Files…")
    # Well past the parent menu's right edge (320) plus the 50 px margin.
    sub.setGeometry(QRect(500, 200, 120, 60))
    sub.show()

    _move_to(menu, QPointF(560, 230))  # inside the submenu
    assert menu.isVisible()
    menu.deleteLater()


def test_hover_menu_closes_when_submenu_hidden(app):
    """The submenu region is only safe while the submenu is actually open —
    the same point with the submenu hidden closes the menu as before."""
    from PySide6.QtCore import QPointF, QRect

    btn, menu = _shown_hover_menu()  # noqa: F841 (keep btn alive)
    sub = menu.addMenu("Add")
    sub.addAction("Files…")
    sub.setGeometry(QRect(500, 200, 120, 60))
    # NOT shown.

    _move_to(menu, QPointF(560, 230))
    assert not menu.isVisible()
    menu.deleteLater()
```

- [ ] **Step 3: Implement the safe-region check**

In `src/starpost/gui/widgets.py`, `HoverMenu.mouseMoveEvent` currently ends:

```python
        if self._owner is not None and self._global_rect(self._owner).adjusted(
            -m, -m, m, m
        ).contains(pos):
            return
        self.close()
```

Change the ending to:

```python
        if self._owner is not None and self._global_rect(self._owner).adjusted(
            -m, -m, m, m
        ).contains(pos):
            return
        # An open child submenu (e.g. "Add ▸") is a separate popup window that
        # can extend past the margin — while it is visible, it is safe too.
        for action in self.actions():
            sub = action.menu()
            if (
                sub is not None
                and sub.isVisible()
                and sub.frameGeometry().adjusted(-m, -m, m, m).contains(pos)
            ):
                return
        self.close()
```

Also extend the class docstring's behavior note — after the paragraph about `sibling_bar`, add:

```python
    A visible child submenu (added with ``addMenu``) is part of the safe
    region as well, so moving deep into it never closes the parent.
```

```python
def test_file_panel_public_add_dialogs(app, monkeypatch, tmp_path):
    """add_files_dialog / add_folder_dialog are the public entry points to the
    Files tab's native add dialogs (used by the toolbar File menu too)."""

    sim_a = tmp_path / "a.sim"
    sim_b = tmp_path / "b.sim"
    sim_a.touch()
    sim_b.touch()

    win = mw.MainWindow(Settings())
    monkeypatch.setattr(
        fl.QFileDialog,
        "getOpenFileNames",
        staticmethod(lambda *a, **k: ([str(sim_a)], "")),

    folder = tmp_path / "runs"

        staticmethod(lambda *a, **k: str(folder)),
```

```python
def test_toolbar_file_menu_structure(app):
    """A File hover-dropdown sits first in the bar (before Run batch) with
    Add ▸ Files…/Folder…, Import data… and Export data…."""
    win = mw.MainWindow(Settings())
    assert win._file_button.text() == "File"
    labels = [a.text() for a in win._file_menu.actions()]
    assert labels == ["Add", "Import data…", "Export data…"]
    add_menu = win._file_menu.actions()[0].menu()
    assert [a.text() for a in add_menu.actions()] == ["Files…", "Folder…"]
    # Placement: File comes before Run batch in the bar.
    widgets = [win._toolbar.widgetForAction(a) for a in win._toolbar.actions()]
    assert widgets.index(win._file_button) < widgets.index(win._run_button)
    win.close()


def test_file_menu_actions_call_slots(app, monkeypatch):
    """Each File-menu action triggers the same slot as its tab-button twin."""
    from starpost.gui.views.file_list import FileListPanel

    calls = []
    monkeypatch.setattr(
        FileListPanel, "add_files_dialog", lambda self: calls.append("files")
    )
    monkeypatch.setattr(
        FileListPanel, "add_folder_dialog", lambda self: calls.append("folder")
    )
    monkeypatch.setattr(
        mw.MainWindow, "_import_data", lambda self: calls.append("import")
    )
    monkeypatch.setattr(
        mw.MainWindow, "_export_data", lambda self: calls.append("export")
    )
    win = mw.MainWindow(Settings())
    add_menu = win._file_menu.actions()[0].menu()
    for action in add_menu.actions():
        action.trigger()
    for action in win._file_menu.actions()[1:]:
        action.trigger()
    assert calls == ["files", "folder", "import", "export"]
    win.close()
```

In `src/starpost/gui/main_window.py`, `_build_toolbar`, immediately after `tb.addWidget(self._toolbar_logo)` and before the `self._run_button = HoverMenuToolButton()` line, insert:

```python
        # File menu: toolbar-level access to the Files tab's add dialogs and
        # the Data tab's portable-CSV import/export — same slots, second entry
        # point. Hover-opens like Run batch.
        self._file_button = HoverMenuToolButton()
        self._file_button.setText("File")
        self._file_button.setAutoRaise(True)
        self._file_button.setToolButtonStyle(Qt.ToolButtonStyle.ToolButtonTextOnly)
        self._file_button.setPopupMode(QToolButton.ToolButtonPopupMode.InstantPopup)
        self._file_button.setToolTip(
            "Add .sim files or folders, import or export portable data CSVs"
        )
        file_menu = HoverMenu(
            self._file_button, owner=self._file_button, sibling_bar=tb
        )
        add_menu = file_menu.addMenu("Add")
        add_menu.addAction("Files…", self.file_list.add_files_dialog)
        add_menu.addAction("Folder…", self.file_list.add_folder_dialog)
        file_menu.addAction("Import data…", self._import_data)
        file_menu.addAction("Export data…", self._export_data)
        self._file_button.setMenu(file_menu)
        self._file_menu = file_menu
        tb.addWidget(self._file_button)
```

`HoverMenu`, `HoverMenuToolButton`, `Qt` and `QToolButton` are already imported in `main_window.py` (used by the Run batch block a few lines below); do not add duplicate imports.

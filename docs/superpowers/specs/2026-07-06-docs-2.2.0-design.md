# Update StarPost_Documentation.md to 2.2.0

**Date:** 2026-07-06
**Status:** Approved

## Problem

`docs/StarPost_Documentation.md` (the full program reference) is version-stamped
**2.1.0** and predates two releases:

- **2.1.1** — Run-batch archives can be **ZIP or 7Z**; the unavailable **RAR**
  option was removed.
- **2.2.0** — the toolbar **Run batch** button became a **hover dropdown**
  (**Full Batch** + **Express batch**); a new **Express batch** window runs a
  saved batch profile quickly; **batch profiles** now also store the report
  format, "Include units", and "Combined report" settings.

As a result the doc is not just missing features — it is **wrong** in one place:
§3.9a still says "7Z and RAR are not currently supported; the run always writes a
`.zip`."

## Goal

Bring `docs/StarPost_Documentation.md` current through 2.2.0: document the new
features, correct the stale archive-format text, and bump the version stamp.

## Scope

- **In scope:** `docs/StarPost_Documentation.md` only.
- **Out of scope, with rationale:**
  - **README.md** — already current (it lists Express batch and ZIP/`.7z`).
  - **§2 Capabilities** in the reference — it has no stale archive claims and no
    existing Run-batch/archive bullet to amend; the detailed reference lives in
    §3, so §2 is left unchanged.
  - **Bug-fix behaviours** shipped alongside 2.2.0 (empty-space deselect in the
    Files/Data trees; leftover hover-outline fixes) — these are fixes, not
    features, and the request is for features. Not documented.
  - **docs/screenplay_plan.md** — an internal demo-script planning artifact; the
    user scoped this to the main reference only.

## Changes (all in `docs/StarPost_Documentation.md`)

### 1. Version stamp

Line 5: `> Version: **2.1.0**` → `> Version: **2.2.0**`.

### 2. §3.2 Toolbar — Run batch becomes a hover dropdown

Rewrite the **Run batch** row of the toolbar table so it reads as a **hover
dropdown** (its menu opens on mouse-over) offering two entries:

- **Full Batch** → the five-tab wizard ([§3.9a Run batch dialog](#39a-run-batch-dialog)).
- **Express batch** → the lean [§3.9b Express batch dialog](#39b-express-batch-dialog),
  for running a saved batch profile quickly.

Keep the existing note that it is **disabled while a run is in progress** (the
whole button is disabled, so neither entry opens mid-run). The "extract straight
to the workspace" aside (right-click → Open) stays.

### 3. §3.9a Run batch dialog — three targeted fixes

- **Intro:** it is opened from **Run batch → Full Batch** (was just "Run batch").
- **Batch profile bar:** add that a batch profile now also stores the **report
  format**, **Include units**, and **Combined report** settings, so loading a
  profile restores them — a profile fully defines its report output. (This is
  also what the Express window reads.)
- **Summary → Archive format** (currently: "ZIP / 7Z / RAR — 7Z and RAR are not
  currently supported; the run always writes a `.zip`, with the other formats
  planned for a future release"): replace with — the **Archive format** selector
  offers **ZIP** or **7Z**, and the run writes the chosen format (`.zip` or
  `.7z`); the previously listed **RAR** option has been removed. Update the
  **Batch run** paragraph's "single archive" wording to note the archive is in
  the chosen format.

### 4. New §3.9b Express batch dialog

Add a new subsection after §3.9a, matching its detail level:

- **Opened from** the toolbar **Run batch → Express batch**. It is the fast path
  for users who already have a saved **batch profile**: pick the profile and
  sources, set the archive options, and run — no five-tab wizard.
- **Batch profile selector (top):** lists the saved batch profiles and is
  **required** — the **Batch run** button stays disabled until one is chosen.
  When no batch profiles exist yet, a note directs the user to create one in
  **Full Batch**.
- **Sources:** the same source picker as the wizard's **Source** tab (`.sim
  files` or `Loaded data sets`, Load / Select All / Clear, tick which to
  include) — but **without** the "Has similar format" step, since the profile
  already defines the outputs.
- **Export options (in the Options column, beneath the source input):** the
  **Archive format** selector (ZIP / 7Z) and **Include dataset .csv**, matching
  the wizard's Summary tab.
- **What the profile supplies:** the reports, saved plots and saved scenes, and
  the report format / Include units / Combined report settings. The user only
  chooses the sources and the archive options.
- **Behaviour and guards** (same as the wizard): STAR-CCM+ is invoked only when a
  `.sim` source must be extracted or a scene rendered (and its executable path
  must be set); warnings for **No data selected** and for a profile that yields
  **nothing to output**. The run writes the same **single archive** (one folder
  per data set) as the wizard, in the chosen format.

dialog** entry, linking to `#39b-express-batch-dialog`.
